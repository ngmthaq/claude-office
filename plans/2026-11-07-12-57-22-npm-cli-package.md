# Title: Plan — Publish claude-office as the `@ngmthaq20/claude-office` npm CLI

- Classification: feature
- Description: Add a new `apps/cli` workspace that bundles the server and web builds into one npm package with `install`, `uninstall`, and `open [PORT]` commands.

---

## Approach Summary / Goal

- Add a new workspace, `apps/cli`, named `@ngmthaq20/claude-office`, with the bin command `claude-office`. Its build copies the bundled server, the SQL migrations, and the web build into `apps/cli/dist`.
- The server gets environment-variable overrides for its data, web, and migrations folders, and its allowed origins follow `PORT`. `pnpm dev` keeps its current behaviour.
- `open` starts the server as a child process (`NODE_ENV=production`), waits until it responds, opens the browser, and stops the server on Ctrl+C.
- Goal: a developer runs `npx @ngmthaq20/claude-office open` and gets the office in the browser with no clone and no build.

## Functional Requirements

- `install`:
  - creates `~/.@ngmthaq20-claude-office`
  - runs the DB migrations there
  - runs `npm install -g @ngmthaq20/claude-office@<same version>`
  - prints a success message
- `uninstall`:
  - asks "Delete data folder … ? (y/N)" before it deletes the data folder
  - `--yes` skips the question
  - runs `npm uninstall -g @ngmthaq20/claude-office`
  - prints what it removed and what it kept
- `open [PORT]`:
  - The port is optional. The default is 4317. A port that is not a whole number from 1 to 65535 shows an error.
  - If the port is busy, it shows a clear error and exits with code 1.
  - It creates the data folder if it is missing. The server runs migrations at start.
  - It opens the default browser at `http://127.0.0.1:<PORT>` on macOS (`open`), Linux (`xdg-open`), and Windows (`start`).
  - Ctrl+C stops the server cleanly and exits.
- Running with no command, `help`, or an unknown command prints usage and exits with code 1 (code 0 for `help`).
- On Node < 24, the CLI shows a clear error.
- The server reads these environment variables:
  - `CLAUDE_OFFICE_DATA_DIR`
  - `CLAUDE_OFFICE_WEB_DIST_DIR`
  - `CLAUDE_OFFICE_MIGRATIONS_DIR`

  When they are not set, the current paths are used, so dev still uses `apps/server/data`.
- `ALLOWED_ORIGINS` uses the real `PORT` (127.0.0.1 and localhost) and keeps 5173 for dev.

## Non-Functional Requirements

- The server still listens on `127.0.0.1` only.
- The CLI has no new runtime dependencies. It uses only Node built-ins (`child_process`, `net`, `readline`, `fs`, `os`).
- The published package contains only `dist/`, `package.json`, and `README.md`.
- The CLI never reads or logs secrets or env values.

## Files in Scope

- Change `apps/server/src/configs/app.config.ts`: env overrides for the data and web folders, and origins built from the port.
- Change `apps/server/src/configs/database.config.ts`: env override for `MIGRATIONS_DIR`.
- Create `apps/server/src/migrate.ts`: opens the DB, runs migrations, prints what it applied, and exits.
- Change `apps/server/scripts/build.mjs`: also builds `dist/migrate.js`.
- Create `apps/cli/package.json`: name, `bin`, `files`, `engines`, `publishConfig.access=public`, the server's runtime deps, and workspace devDeps on server and web for build order.
- Create `apps/cli/tsconfig.json`.
- Create `apps/cli/scripts/build.mjs`: esbuild for `src/cli.ts` → `dist/cli.js` (with shebang), then copies the server dist → `dist/server`, migrations → `dist/server/migrations`, and the web dist → `dist/web`.
- Create `apps/cli/src/cli.ts`: parses the command and routes it.
- Create `apps/cli/src/commands/install.command.ts`, `uninstall.command.ts`, `open.command.ts`.
- Create `apps/cli/src/utils/*.ts`: paths, port check, browser open, confirm prompt, run npm. Split them as the existing code style suggests.
- Create `apps/cli/README.md`: usage for the three commands.
- Change the root `package.json` only if the `build` order needs it.

## Risks & Assumptions

- Assumption: I added the `--yes` flag for `uninstall` so it works without a terminal prompt. You did not ask for it.
- Assumption: when `install` runs the global install, it pins the same version that is running now.
- Risk: `better-sqlite3` is a native module. npm installs a prebuilt binary, but on a rare OS/Node combination it builds from source and needs build tools.
- Risk: if the package is published with plain `npm publish`, the `workspace:*` devDeps stay as they are in the published `package.json`. They are dev-only, so users are not affected. Using `pnpm publish` from `apps/cli` replaces them with real versions. I recommend `pnpm publish --access public`.
- Risk: `uninstall` started from the global `claude-office` command removes its own package while it runs. This is fine on macOS/Linux. The delete step runs before the npm step.
- Testing workflow is `Skip-Testing`, so there are no tester tasks. I will check the work at review with `pnpm build`, `npm pack`, and a local run of the packed tarball.
