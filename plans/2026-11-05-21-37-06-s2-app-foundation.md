# Title: Plan — S2 App foundation

- Classification: feature
- Description: Set up the pnpm monorepo with a Fastify + WebSocket server on `127.0.0.1`, shared Zod event schemas, SQLite migrations, a React + Vite shell with a WebSocket client that reconnects, and Kenney CC0 art in `assets/`.

---

## Approach Summary / Goal

- One pnpm workspace has 3 packages:
  - `apps/server` (Fastify 5, `@fastify/websocket`, pino, `better-sqlite3`)
  - `apps/web` (React 19, Vite, Zustand)
  - `packages/shared`: the Zod event schemas, with one public entry file
- The root `pnpm dev` runs the server and Vite together. Vite sends `/ws` on to the server, so the browser uses only one address.
- Each side checks every WebSocket message with the shared schemas. A bad message is logged and dropped, and nothing crashes.
- The art is a separate job, so a second developer works on it at the same time.
- **Goal:** one clean pattern from `CODING_CONVENTIONS.md` that S3 and later stories only add to.

## Functional Requirements

- `pnpm install && pnpm dev` starts both apps. `pnpm lint`, `pnpm typecheck` and `pnpm format:check` pass.
- The server listens on `127.0.0.1:4317` only. The WebSocket route is `GET /ws`. It sends a `hello` event (with the server version and time) when a client connects.
- **Shared events:**
  - A `ServerEvent` union and a `ClientEvent` union, each a Zod discriminated union on `type`. To start, there is `hello` (server) and `ping`/`pong`, plus an `error` event.
  - `parseServerEvent` and `parseClientEvent` return a safe result, and never throw.
- **Server:** a bad client message is logged with its type or shape, but never the whole payload, and the server sends an `error` event back.
- **Web:** a bad server message is logged to the console and ignored.
- **SQLite:**
  - The DB file is `apps/server/data/claude-office.db`, which git ignores. The server creates the folder at startup.
  - A small runner applies the SQL files in `apps/server/src/db/migrations/` in order and tracks them in a `schema_migrations` table.
  - The first migration is only a baseline (`0001_init.sql`) with no app tables.
- **Web shell:**
  - The `use-connection-store.ts` Zustand store holds the state: `connecting`, `connected` or `disconnected`.
  - The WebSocket client reconnects by itself with backoff (1 second, up to 10 seconds).
  - A small status badge in the header shows the state.
- **Art:**
  - `assets/` has the chosen Kenney CC0 packs.
  - `assets/CREDITS.md` lists each pack with its name, URL, license (CC0) and what it is used for.
- `git init` with a full root `.gitignore`. There are no commits.

## Non-Functional Requirements

- **Security:**
  - Bind to `127.0.0.1` in code. The host is not something you can set to `0.0.0.0`.
  - Never log secrets or message payloads.
- **Code:**
  - TS `strict`, no `any`. ESLint flat config and Prettier, using the style rules (semicolons, single quotes, 2 spaces, width 100, trailing commas everywhere).
  - Path aliases are `@/` inside each app, and the shared package is `@claude-office/shared`.
  - No barrel files, except the shared entry file.
- **Errors:** one error boundary in the web app shell.
- **Node:** set `engines.node` to `>=24`. Set the pnpm version in `packageManager`.

## Risks & Assumptions

- **Assumption: ports.** The server uses `127.0.0.1:4317` and Vite uses `127.0.0.1:5173`, which proxies `/ws`. Both are constants in config.
- **Risk: native build.** `better-sqlite3` needs a native build. pnpm 10 blocks install scripts by default, so the root `package.json` must allow it through `pnpm.onlyBuiltDependencies`.
- **Risk: art fit.** Kenney's style is simple. There may be no pack that is exactly an "office", so the developer may combine an indoor or furniture pack with a character pack. If no pack has walk frames, `CREDITS.md` says so, and S4 deals with it.
- **Assumption: downloads.** The developer downloads the zips from kenney.nl into the scratch folder first, then copies only the PNG sheets and the license file into `assets/`.
- **Assumption: the "other device" check.** Skip-Testing applies, so there are no tester tasks. To prove the server listens on `127.0.0.1` only, `lsof` must show the server bound to `127.0.0.1`, and a request to this Mac's LAN IP must fail.
- **Assumption: git.** `git init` only. There are no commits and no remote. You commit yourself.
